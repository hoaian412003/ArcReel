# H3 Ref2VA 提示词档：六段英文载荷是单元正文的派生物，正文仍是内容真相

MiniMax H3 的全参考（Ref2VA）提示词有固定的六段英文结构（`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`），资产以 `<Subject N>` / `<Picture N>` / `<Audio N>` 标签指代。通用渲染把单元正文包进中文的主体绑定、风格块与 `Avoid` 行，无法产出这套结构，创作者也没有办法控制最终下发的文本。

决定给项目加一个**提示词档**设置（`video_prompt_profile`：`default` / `h3_ref2va`，缺省即默认档），仅参考生视频的剧情与解说项目可选 H3 档：

- 单元正文（`text`）仍是内容真相（`docs/adr/0064`）：引用、声音绑定、时长准入都从它派生，H3 档不改这一点。
- 六段载荷（`h3_prompt`）是正文的**派生物**，随单元落盘，并记下写入时的正文指纹；正文被改动后指纹不再匹配，载荷即过期，须重新生成，不做静默沿用。
- 提示词编写在 H3 档下由专用模版一次产出正文与六段载荷。载荷里的资产用 `@[名称]`、`<Picture @[名称]>`、`<Audio @[名称]>` 占位，生成时按实际随请求发出的参考图 / 参考音频顺序解析成数字标签，编号因此不会与被能力上限裁剪后的请求错位。
- 提示词编写产出时机械校验载荷与正文一致：不得直接写数字标签、只能引用正文已引用的资产、正文引用的每个资产都要定义、分镜时间戳严格递增且不超时长、角色台词逐字进入 `<d>`、画外音不进 `<d>`、正文一律英文（`<d>` 与画面文字除外）。
- 渲染出口 `render_video_unit_prompt` 在 H3 档下下发解析后的六段，不再附加通用渲染的主体绑定、风格块与 `Avoid` 行；准入把「载荷缺失、过期、引用未随请求发出、超长」都判为阻断问题，不回落到通用渲染。
- 创作者可以在单元卡片上手写六段（同一套机械校验），也可以「重新生成 H3 提示词」：以现有正文为准、只重写六段，正文不动。

## Considered Options

- **载荷取代正文成为单元的内容真相**：最忠实于 H3 的结构，但引用派生、声音绑定、准入与时间线都建立在正文上，等于重写这些机制。
- **只换提示词编写的模版、渲染仍走通用路径**：改动最小，但下发的文本仍带中文包装，创作者依旧控制不了最终提示词，也拿不到 H3 指南要求的结构。
- **缺载荷时回落到通用渲染并给警告**：不会阻断生成，但会下发与该设置承诺不符的提示词，还在悄悄花钱。

## Consequences

- 每个 H3 档单元多存一份六段文本，提示词编写的产出与费用约翻倍；正文改动后要重新生成才能继续生成视频。
- 手写单元与切换到 H3 档之前编写的单元没有载荷，生成前要先生成一次。
- 六段写作规范出自 MiniMax H3 提示词写作指南，模版用自己的话转述规则并注明出处，不逐字转载。
- 广告 / 短片项目暂不支持 H3 档；参考音频的 `<Audio …>` 引用只在项目选了参考音频绑定方式、且角色确有可用参考音频时才允许。
