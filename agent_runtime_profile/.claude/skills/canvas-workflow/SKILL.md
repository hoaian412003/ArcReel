# 节点画布工作流

画布是用户正在眼前看着的创作图，你的每一次改动都会实时出现。目标是把「提示词 → 图片 → 起始帧 → 视频单元」摆成清楚的一条链，并替用户运行。

## 开始前

1. 先调用 `get_canvas`，读清现有节点、连线、展示中的集与已存的模板；不要凭空新建重复的节点。
2. 想看某一集的单元、起始帧联合图和 H3 提示词，先 `canvas_set_episodes` 展示该集（仅参考生视频项目）。项目推导的节点只读，不能增删改。
3. 用户在画布上选中了节点时，指令里会带上节点 id：围绕它工作，不要动无关的节点。

## 搭链的规则

- 节点有类型：`text`（提示词 / 备注）、`image_generate`（图片供应商）、`video_generate`（视频供应商：提示词 + 可选起始帧图 → 视频）、`audio_generate`（语音供应商：文本 → 语音）、`h3_writer`（H3 写作），后四类可运行。图片 / 视频 / 语音节点由用户上传或运行产出，你不能新增。
- 句柄只在同数据类型之间连：text→`prompt`（text）、图片→`refs`（image）、图片→视频供应商的 `frame`（起始帧）、text→语音供应商的 `text`、单元→H3 写作的 `units`（unit）。连错会被拒绝，按返回的问题改正。
- 把 `image_generate` 的输出句柄 `image` 直接连到另一个 `image_generate` 的 `refs`（或 `video_generate` 的 `frame`），下游运行时会取上游**最近一次**产出的图，重跑上游后无需重连。
- 视频和语音都比图片贵且慢：运行前确认 `duration_seconds` 是所用视频模型支持的时长；视频进行中服务被重启会让该节点失败，需要重新运行。
- 放置新节点前看现有节点坐标：节点宽约 280，同列纵向间隔取 ≥ 300，沿输入→输出从左到右排；不要叠在一起。
- 参考图在请求里按**从上到下的摆放顺序**编号成「图1」「图2」……运行时服务端会自动附上编号说明；提示词里要指认某张参考图时就写「图N」。

## 运行

- `canvas_run_node` 只提交任务并立刻返回任务 id，**不等结果**。运行后用 `get_canvas` 查看进度：输出节点的 `status` 是 `queued` / `running` / `done` / `failed`，失败时节点的 `error` 写明原因。
- 有上下游依赖时按先上游后下游的顺序运行，并确认上游已 `done` 再跑下游；上游没有产物时下游拿不到参考图。
- 图片节点带 `stale: true` 说明它生成之后输入已经变了，询问用户是否需要重跑，不要擅自批量重跑（每次运行都计费）。
- `h3_writer` 会重写所连单元的 H3 提示词，单元正文原样保留。运行前确认用户要覆盖的是哪些单元。

## 模板

用户反复要同一套结构时，用 `canvas_save_template` 把选中的文本 / 供应商 / H3 写作节点存成模板，之后用 `canvas_use_template` 在新位置展开。产出的图片、上传的图片和项目推导节点不会进模板。

## 不要做

- 不要为了"整理"而删除用户的节点或连线；正在排队或运行的节点删不掉，也不要尝试绕过。
- 不要在没有被要求时指定 `model`：节点不填就用项目默认的图像模型。
- 不要用画布工具替代项目的审阅流程：剧本、导演、起始帧的审核仍按各自的工作流进行。
